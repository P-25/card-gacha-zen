# Riftgard — Game Feature Report

> A full breakdown of every system in this project: what it is, how it works mechanically, and where it lives in the code. Generated by reading the actual implementation (types, Redux slices, config files, and components), not just the UI.

**Stack:** Next.js 16 (Pages Router) + React 19, Redux Toolkit for state, Framer Motion for animation, `crypto-js` for save encryption. Single-page app — there is effectively one route (`src/pages/index.tsx`); all "screens" are components swapped in and out of a phone-frame shell.

---

## 1. What the game is

Riftgard is a mobile-style **gacha card collector** with a lightweight **3v3 stat-duel battler** bolted on. The loop is: summon cards with gems → build a 3-card team → fight AI opponents for currency/XP → level up cards and your account → summon more. There is no PvP, no server, no real-money purchases — everything is local, client-side, and persisted to encrypted `localStorage`.

---

## 2. App structure & navigation

- `src/pages/_app.tsx` wraps the app in the Redux `Provider`, mounts a persistent `<BackgroundMusic>` player, and shows `<StartScreen>` as a splash overlay until the player taps to begin (this replays on every full page reload — it's session state, not persisted).
- `src/pages/index.tsx` is the only real page. It uses `useGameState()` (`src/hooks/useGameState.ts`) to track a single `appState` string that acts as the "router": `loading | home | gacha | quests | collection | battle | deck | shop | social | offering-rates | tier | settings`. Switching screens is just `setAppState(...)`, not Next.js routing.
- `GameLayout.tsx` renders a fixed mobile-phone-sized frame, cross-fades between screens with `AnimatePresence`, and hosts the persistent bottom nav.
- On every mount, the app dispatches a quest daily/weekly reset check and logs a "LOGIN" quest event — i.e. opening the app counts toward the login quest every time.
- `deck` and `social` app-states exist but have no nav entry and currently render a generic "Coming Soon" placeholder screen.

## 3. Start screen & first impressions (`StartScreen.tsx`)

- Full-screen splash: ~2.5s simulated loading, then "P26 Games Presents" branding, an animated logo, and a "Tap to Start" prompt.
- Tapping anywhere plays an 800ms zoom/blur exit animation before revealing the game.
- Footer shows a static `Version: 1.0.0 (beta)` string and the player's `#tag`.

## 4. Core data model

- **Rarity** — only three tiers exist: `COMMON`, `UNCOMMON`, `RARE` (`src/config/rarityTypes.json`). No Epic/Legendary tier, despite some unused UI color configs hinting one was planned.
- **Card** (`src/types/game.ts`) — `id`, `name`, `rarity`, `setName`/`setId` (elemental grouping), `level`, `state: {pow, spd, def}` (the three stats), `experience`, flavor `description`, per-card `backgroundColor`/`textColor` theming. Cards have **no HP, no abilities, no elemental advantages, no status effects** — they are pure stat blocks.
- **Total Power (TP)** — the unifying strength metric used everywhere: `pow + spd + def`. Drives deck strength display, battle-mode gating, and battle-tier progression.
- **24 cards total**, in 6 elemental sets of 4 (Earth, Water, Wind, Dark, Fire, Light): 12 Common, 8 Uncommon, 4 Rare. Higher rarity = higher and more balanced total stats (e.g. a Common totals ~30 TP, a Rare ~75 TP).
- **Resources** — two non-card gacha pulls exist: "Spark of Fortune" (Common, grants 50 gold) and "Luminous Stash" (Uncommon, grants 100 gold).
- Every owned card copy gets a unique `instanceId`, so duplicates of the same card are tracked as separate inventory entries.

## 5. Player progression

**Currencies** (`src/store/slices/playerSlice.ts`):
- **Gold** — starts at 100. Earned from quests, player level-ups (+300/level), battle-tier-ups (+1000 flat), and gold-resource pulls from the gacha. Spent on shop purchases and card leveling (10 gold per fodder card).
- **Gems** — starts at 900. Earned from quests, player level-ups (+100/level), battle-tier-ups (+30 flat). Spent almost exclusively on gacha summons. The shop's "gem packs" are oddly priced *in gold*, not real money — there is no IAP flow anywhere in the codebase.

> Note: a second, unused "new player generator" (`generateRandomPlayerInfo` in `rarityStyles.ts`) hands out 1000 gems / 500 gold instead — a leftover inconsistency, not something the live game path uses.

**Account level:** XP-to-next-level is always `currentLevel × 100`. `addPlayerExp`/`addRewards` roll level-ups in a loop, but the reward (**+100 gems / +300 gold per level gained**) is only granted when the player explicitly acknowledges a `LevelUpPopup` on the Home screen (`acknowledgeLevelUp`), decoupled from the moment the XP threshold was crossed.

**Profile & customization** (`ProfileModal.tsx`):
- Name/tag, avatar (`profileIcons.json` — 3 icons total), and a level/XP bar.
- Avatar unlock text exists in config ("Reach Level 5" / "Reach Level 10") but is **not enforced by any code** — only the default icon is ever actually unlocked automatically. This looks unfinished.
- 3 trophy/badge slots in the profile modal are decorative placeholders with no backing system.

## 6. Card collection & leveling (`CollectionScreen.tsx` and friends)

- Grid view of every owned card instance, filterable by rarity and sortable by Total Power, infinite-scrolled 24 at a time.
- Tapping a card opens a detail sheet with stats, rarity, and a level progress bar, plus two actions:
  - **Level Up** — fully implemented (see below).
  - **Rank Up** — **stubbed**, permanently disabled, logs `"Debug - Rank up coming soon"`. Duplicates are *not* converted into a rank-up material despite the UI hinting at it.

**Card leveling (the actual "duplicate" sink):**
Duplicates/unwanted cards are fed directly to another card as XP "fodder" — there is no shard-conversion step.
- Fodder XP value = base amount by rarity (**Common 50 / Uncommon 100 / Rare 200**) × the fodder card's own level (capped at 5000 XP per card in the UI helper).
- Costs **10 gold per fodder card** selected.
- XP-to-next-level for a card is `currentLevel × 100` (same curve as player XP).
- Each level gained adds **+2 POW / +2 SPD / +2 DEF**.
- A card's level is capped at the **player's account level** — cards can never outlevel you.
- Cards currently placed in your battle deck (tracked via a `localStorage` key, see §9) are locked from being used as fodder.
- Confirming plays a full "feeding" animation with a before/after stat comparison popup.
- A `[DEV] Add 10,000 Gold` debug button is still present in this screen's UI.

## 7. Deck building (3v3 team select)

- **"Echo Loadout" screen** (`SelectCardsPhase.tsx`) — pick 3 cards from your full inventory into 3 slots; tapping a filled slot removes it.
- **"Form Team" screen** (`DeckSelectionScreen.tsx`) — shows the chosen deck's summed POW/SPD/DEF/TP against the selected battle mode's power requirement. Requires exactly 3 cards to proceed; if under-powered, a warning modal still lets you fight anyway. Includes an "Auto-form" auto-pick button.
- The active deck is mirrored into `localStorage["player_deck_v1"]` so the Collection/Level-Up screens know which cards are "in use" and should be locked from fodder consumption.

## 8. Summon / gacha system

**Banner** (`src/config/summons.json`) — one live banner, "Dragon Slayer Rate Up":

| | |
|---|---|
| Single pull | 10 gems |
| 10× pull | 90 gems (10% discount) |
| Common rate | 85.40% |
| Uncommon rate | 13.20% |
| Rare rate | 1.40% |
| Soft pity starts | pull 60 |
| Soft pity ramp | +5 percentage points to Rare chance per pull past 60 |
| Hard pity | pull 90 (Rare guaranteed) |
| Pity reset | on any Rare pull |

Pity is tracked per-banner in `pitySlice.ts` and the actual roll math lives in `src/lib/gameLogic.ts::performSummon`: hard pity forces a Rare at pull 90; between pulls 60–89 the Rare rate climbs linearly; below 60 it's a flat roll, with the Common/Uncommon split renormalized proportionally to fill the remaining probability.

**Pull flow:** validates gem balance → charge-up animation (~2.5s magic-circle SVG with runes/particles) → flash → reveals results one at a time (or "Skip All") with rarity-colored effects and a sparkle overlay + "NEW!" badge for first-time cards → 10-pulls show a summary grid with "Claim All". Each summon also grants the player 10 XP per pull and ticks the "SUMMON" quest counter.

**Offering Rates screen** — an accordion breaking down exact drop percentages per card, grouped by rarity, reachable from an info button on the summon screen.

A low-gem warning modal appears if you try to pull without enough currency, pointing you toward quests or the shop.

## 9. Battle system

Despite the "3v3" framing, combat is a **best-of-3 stat-duel**, not simultaneous 3-vs-3 combat — each side fields 3 cards, one is played per round.

**Flow:** Deck select → Matchmaking (a fake 3s "searching" delay while an AI deck is generated) → Versus splash (3s) → Battle → Result/Rewards.

**How a round works** (`BattlePhaseNew.tsx`):
1. A random active stat (POW, SPD, or DEF) is revealed via a ~1.2s slot-machine animation.
2. Both sides pick one of their remaining cards — the player has a 20s timer (auto-picks randomly on timeout); the **AI picks a uniformly random valid card** with no strategy at all.
3. Whichever card has the higher value in the revealed stat wins the round outright (`uStat > oStat`) — there is no damage formula, no elemental bonuses, no randomness beyond the stat reveal and card choice.
4. A ~4–7s cinematic plays (tension → charge → clash → particle/shockwave impact → card-shatter destroy) before the next round.
5. After 3 rounds (all cards played), the match ends.

**Result & rewards:**
| Outcome | Rewards |
|---|---|
| Perfect win (3-0) | 20 EXP, 30 gold, 5 gems |
| Normal win | 10 EXP, 20 gold |
| Draw | 10 EXP, 20 gold |
| Loss | 10 gold only |

Wins tick the "BATTLE_WIN" quest counter.

**Battle modes** (Battle tab has 3 entry points):
- **Story Mode** — button exists, unimplemented (`console.log` only).
- **Step-Up Battle** — a fixed 4-rung difficulty ladder with explicit opponent rosters and power gates:

  | Difficulty | Required TP | Opponent deck |
  |---|---|---|
  | Beginner | 100 | 1× Common Lv3, 2× Common Lv1 |
  | Intermediate | 225 | 2× Rare Lv1, 1× Uncommon Lv6 |
  | Advanced | 420 | 2× Rare Lv12, 1× Rare Lv11 |
  | Expert | 600 | 3× Rare Lv22 |

- **Wild Mode** — opponent deck is dynamically power-matched to your own deck's total power (buffs a random 3-card AI deck up toward your average card power) so it's always a roughly fair fight, regardless of your progress.

Opponent card leveling reuses the same "+2 stats per level" rule as player card fusion.

## 10. Battle Tier system (meta-progression)

A separate account-rank system, unrelated to win/loss streaks — it tracks **roster strength**, not battle record.

- `player.battleTier` starts at 1.
- Your **TP for this system** = sum of POW+SPD+DEF across your **top 3 cards by power** (not necessarily your active deck).
- Threshold to advance from tier *N* is `N × 100` TP (linear: 100, 200, 300…).
- When eligible, an "Increase Tier" button plays a charge/flash animation (with haptic vibration) and grants a flat **+30 gems / +1000 gold**, then tier increments by 1.
- Your current tier is shown as a persistent badge in the top bar, and higher Step-Up battle difficulties require higher deck TP — so leveling cards → raising tier → unlocking harder fights is the game's core progression spine.

## 11. Quest system (`QuestScreen.tsx`, `quests.json`)

Three tabs: **Daily**, **Weekly**, and **All-time** (labeled "Achievements").

- **8 quests total**, tracking 4 action types: `LOGIN`, `BATTLE_WIN`, `SUMMON`, `CARD_LEVEL_UP`.
  - Daily: log in, win 1 battle, win 3 battles, summon once, level up a card once.
  - Weekly: win 10 battles, summon 5 times.
  - All-time: win 100 battles total (a large lifetime achievement).
- **Progress milestones** — completing a set number of quests within a tab unlocks a bonus chest reward (e.g. 3 daily quests → 30 gems + 300 gold; 5 daily → 50 gems/500 gold/100 XP).
- **Resets:** Daily resets on local-midnight date rollover; Weekly resets after 7+ days elapsed or when a Sunday→Monday boundary is crossed. Checked once on every app load.
- A hidden **"Secret Reset Button"** (a nearly invisible X in the corner) triggers a full save wipe (`localStorage.clear()` + reload) — a dev/debug affordance left in the shipped UI.
- The "Resets in: 14h 23m" label is static text, not a live countdown.

## 12. Shop (`ShopScreen.tsx`, `shopConfig.ts`)

Three sections, everything purchasable with **gold** except summons themselves:
1. **Featured Cards** — 3 hand-picked cards direct-purchasable for a flat gold price (e.g. a Rare for 12,000g). Shows an "Ends in 2d 4h" label that is hardcoded, not a real countdown.
2. **Random Packs** — Uncommon Pack (1,500g, random Uncommon) and Common Pack (250g, random Common).
3. **Gem Shop** — buy 10/100/1,000 gems for 1,000/10,000/100,000 gold respectively. (No real-money purchases exist in this project.)

Buying a card reuses the same reveal animation as gacha pulls; buying gems shows a simple success popup instead.

## 13. Audio & settings

- **Background music** — a single always-mounted looping track (`wind_bg.mp3`), autoplay-with-fallback (starts on first click/keypress if the browser blocks autoplay).
- **SFX** — click, summon-loop, and rarity-aware card-reveal sounds, wired into nearly every button in the UI.
- **Settings screen** — deliberately minimal: just two toggles, **Mute Music** and **Mute SFX**. No volume sliders, no graphics/language/account options.

## 14. Persistence & save system (`src/lib/storage.ts`)

- Everything is saved to **browser `localStorage`**, AES-encrypted via `crypto-js` before writing.
- Four keys are persisted: `player_state`, `pity_state`, `settings_state`, `quest_state` — resaved after *every* Redux action dispatch.
- The encryption key is a `NEXT_PUBLIC_` env var (bundled into client JS, so visible to anyone inspecting the app) with a hardcoded fallback if unset. This is best understood as **casual-tamper resistance**, not real security — a determined user can still read/edit their save.
- On load, `hydrateStore()` reads all four keys before the app dispatches anything, so old saves don't get clobbered by default state; it also back-fills fields for older save formats (e.g. adding `battleTier` if a save predates that feature).

## 15. Known gaps / unfinished features

For transparency, here's everything found that's visibly incomplete or stubbed in the current build:

- **Rank Up** (card mechanic for duplicates) — UI present, logic is a no-op.
- **Profile icon unlock conditions** — defined in config, never actually enforced.
- **Deck screen** — no dedicated UI (uses Collection/Level-Up flows instead); "Coming Soon" placeholder if reached directly.
- **Social screen** — placeholder only, no nav entry point.
- **Story Mode** — button present, does nothing.
- Shop and Quest countdown timers are static strings, not live.
- Two developer-only affordances ship in production UI: the Quest screen's hidden save-wipe button, and Level-Up screen's "+10,000 gold" debug button.
- Two different "new player" starting-currency definitions exist in the code (900 gems/100 gold vs. 1000 gems/500 gold) — only the first is actually used by the live game.
- Battle debug console logging (deck tables) still fires in the opponent-generation code.
